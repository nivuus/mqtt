# Guest network VPN Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** send all `publicBridge` guest traffic (and their DNS) through a ZoogVPN OpenVPN tunnel managed from Home Assistant, falling back to Orange when the tunnel is down.

**Architecture:** NetworkManager owns the tunnel (one VPN profile `nivuus-guest-vpn`, imported from the uploaded `.ovpn`), and the profile carries its own routing table, policy rules and its binding to the existing firewalld zone `external`, so everything exists exactly while the tunnel is up; the agent never touches firewalld. The mqtt agent imports profiles, toggles the tunnel, reconciles the DNS DNAT table and publishes state to HA over MQTT. A new HA integration `nivuus_vpn` (in `home-manager`) uploads the file over the agent's WebSocket channel.

**Tech Stack:** TypeScript + jest (mqtt agent), NetworkManager 1.52 + `network-manager-openvpn`, firewalld (nft backend), nftables, Python HA custom integration (`home-manager`, standalone test scripts).

**Spec:** `docs/superpowers/specs/2026-11-09-guest-vpn-design.md` (read it first).

## Global Constraints

- English code, comments, logs, commit messages; conventional commit messages.
- mqtt repo: max **200 lines** per source file; home-manager / suite: max 500.
- Never log, publish, or persist the VPN password or `.ovpn` key material (agent logs, `execute_argv` logs its argv: **no secret may ever be an argv element**, MQTT, HA config entry, HA history).
- Shell from a Claude session: wrap in `bash -c '...'`; `systemctl` does not work, use `dbus-send` (mqtt `CLAUDE.md`).
- Base branch: `origin/main` **after** `fix/websocket-hardening` is merged (it changes `WebSocketServer.ts` / token handling). mqtt branch `feat/guest-vpn`; home-manager branch `feat/nivuus-vpn`. Protected-main repos merge by squash; PR titles conventional, in English.
- Fixed names used across tasks: NM profile id `nivuus-guest-vpn`; tun device `nvguest0`; routing table `200`; firewalld zone for the tun: the existing `external`; nft table `inet nivuus_guest_vpn`; agent feature key `guest_vpn`; WebSocket feature `vpn`.
- **Never break internet on `localBridge`** (owner, after the 2026-11-09 incident — spec "Safety on the live host"). No code and no step ever runs `firewall-cmd --reload`, creates a firewalld zone/policy, or restarts NetworkManager/firewalld. Implementation and validation happen on the bench VM (Task 1) — **nothing touches the live host until Task 10**, and Task 10 runs only with the owner present, behind a dead-man switch.
- Nothing is deployed, pushed or installed on the host without the owner's go-ahead.

## Review Focus

1. **Tunnel down mid-session** → guests keep browsing via Orange within seconds, DNS included (DNAT removed), HA shows "on Orange". Test in Task 5 (`reconcile removes DNAT when not connected`) and Task 9.
2. **A `.ovpn` with `<ca>` inline vs a separate `ca.crt`, CRLF line endings, a UTF-8 BOM** → all import. Tests in Task 2.
3. **Wrong ZoogVPN password** → state `error` with NM's reason, guests on Orange, no infinite tight loop. Test in Task 4 (`status maps failed activation to error`), observed in Task 9.
4. **`firewall-cmd --reload` or firewalld restart while up** → guests still exit through the tunnel. Test in Task 5 (`reconcile re-creates missing table`), observed on the bench (Task 1 Step 6).
5. **Re-upload while connected** → old profile replaced, reconnects with the new one, still enabled. Test in Task 3 (`import replaces an existing profile and keeps autoconnect`).
